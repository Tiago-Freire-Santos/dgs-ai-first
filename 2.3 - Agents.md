## Product Rules & Guardrails

> **Audiência:** este arquivo é lido por agentes de IA (Claude Code, GitHub Copilot)
> e por membros humanos do time. As regras aqui definem o comportamento esperado
> do assistente NovaTech e as restrições que impactam geração de código.
>
> **Fonte de verdade:** `specs/query-endpoint/requirements.md`  
> **Guardrails completos:** `specs/query-endpoint/requirements.md` → seção 5 (Verification Criteria)  
> **Linguagem ubíqua:** este arquivo é a referência canônica de termos do domínio.
> Toda geração de código, resposta do assistente e documentação deve usar
> os termos desta seção sem variação.

---

### 1. Comportamento obrigatório do assistente (DEVE)

Todo código gerado que produza ou manipule respostas do assistente **deve**
respeitar estas regras sem exceção:

---

#### DEVE-01 — Citar fonte em toda afirmação factual

Toda resposta do assistente deve incluir ao menos uma citação de fonte no
formato canônico abaixo. Sem citação, a resposta não deve ser retornada.

```
// Formato canônico de citação — use exatamente este formato
// [FONTE: <doc_id> · <version> · <section>]

// Exemplos VÁLIDOS:
[FONTE: POL-001 · v3.1 · §3.1]
[FONTE: PROC-042-v2 · v2.0 · §2.1]
[FONTE: SLA-2024 · v2024.1 · §2]

// Exemplos INVÁLIDOS — nunca gerar:
[FONTE: PROC-042]           // sem versão
[FONTE: PROC-042 · §2.1]    // sem versão
Fonte: SLA-2024             // formato livre
```

---

#### DEVE-02 — Incluir `source_document` no JSON de retorno

O campo `source_document` é obrigatório no contrato de resposta da API,
mesmo quando a confiança for baixa. Nunca omitir, nunca retornar `null`.
Ver tipo `QueryResponse` em `src/shared/types.ts`.

```typescript
// CORRETO — sempre presente
{
  answer: string,
  source_document: {
    doc_id: string,       // ex: "PROC-042-v2"
    version: string,      // ex: "v2.0"
    section: string,      // ex: "§2.1"
    confidence: number    // 0.0 – 1.0
  }[],                    // array — pode haver mais de uma fonte
  contradiction_flag: boolean,
  gap_flag: boolean
}

// INVÁLIDO — nunca gerar
{
  answer: string,
  source_document: null   // proibido
}
```

---

#### DEVE-03 — Responder em português formal

O assistente opera em ambiente de atendimento interno brasileiro.
Todo texto gerado para o campo `answer` deve ser em português formal,
sem gírias, sem abreviações não padronizadas, sem emojis.

---

#### DEVE-04 — Sinalizar contradição documental

Quando dois documentos divergirem sobre o mesmo fato (ver lista em
`prompts/system-prompt.md` → seção "Contradições conhecidas"),
o campo `contradiction_flag` deve ser `true` e a resposta deve
apresentar ambos os valores com identificação de versão e data.

---

#### DEVE-05 — Sinalizar gap documental

Quando a informação vier exclusivamente do FAQ-Atendimento
(`source_type: "faq_informal"`), o campo `gap_flag` deve ser `true`
e a resposta deve incluir aviso explícito de ausência de documento normativo.

---

### 2. Comportamento proibido (NÃO DEVE)

Todo código gerado que produza respostas do assistente **não deve**
permitir os comportamentos abaixo. Onde indicado, a proibição é
aplicada via validação determinística em `src/services/response-validator.ts`.

---

#### NDEVE-01 — Não gerar valores numéricos sem âncora documental

Prazos, multiplicadores regionais, fatores de peso, percentuais de SLA,
valores de seguro — nenhum valor numérico pode aparecer na resposta sem
estar literalmente presente nos chunks recuperados.

> **Enforcement:** `src/services/response-validator.ts` — verificação de grounding

---

#### NDEVE-02 — Não afirmar que carga perigosa pode ser devolvida pelo processo padrão

Cargas perigosas (classes 1–6 ANTT) têm exceção explícita na POL-001 §3.2.
A regra geral de 7 dias úteis da POL-001 §3.1 **não se aplica** a essa categoria.
Qualquer resposta que contenha os dois em conjunto deve ser bloqueada.

> **Enforcement:** `src/services/response-validator.ts` — detecção de padrão proibido

```typescript
// Padrão proibido — o validator bloqueia respostas que contenham
// simultaneamente: "carga perigosa" + valor de prazo + "devolução"
// Ver: response-validator.ts → validateDangerousGoodsReturn()
```

---

#### NDEVE-03 — Não inventar tiers de cliente

Existem exatamente 3 tiers: `Gold`, `Silver`, `Standard`.
Qualquer outro valor (`Platinum`, `Premium`, `Bronze`, `VIP` etc.)
deve ser rejeitado no input e corrigido proativamente na resposta.

> **Enforcement:** `src/functions/query/validator.ts` — validação de input

```typescript
// Em src/shared/types.ts — lista exaustiva e imutável
const VALID_TIERS = ['Gold', 'Silver', 'Standard'] as const;
type ClientTier = typeof VALID_TIERS[number];

// NUNCA adicionar tiers aqui sem:
// 1. Aprovação do Product Specialist
// 2. Atualização do SLA-2024
// 3. Reabertura do ADR-0003
```

---

#### NDEVE-04 — Não citar documento sem versão quando existem múltiplas versões

Para documentos com múltiplas versões ativas, a versão é obrigatória na citação.

Lista atual de documentos com múltiplas versões (`MULTI_VERSION_DOCS` em `response-validator.ts`):
- `PROC-042` → deve ser `PROC-042-v1` ou `PROC-042-v2`

> **Enforcement:** `src/services/response-validator.ts` → `validateSources()`

---

#### NDEVE-05 — Não executar ações em sistemas externos

O query endpoint é somente leitura. Nenhuma função de escrita em sistemas
transacionais deve ser adicionada a `src/functions/query/`.

> **Enforcement:** arquitetural — ausência de tool use de escrita no endpoint (SB-01 do requirements.md)

---

### 3. Comportamento de fallback (QUANDO EM DÚVIDA)

---

#### DUVIDA-01 — Baixa confiança

Se o score médio dos chunks recuperados estiver abaixo do threshold
configurado em `src/shared/config.ts` → `SEARCH_CONFIDENCE_THRESHOLD`,
a resposta deve ser prefixada com aviso e `confidence` deve refletir
o valor real.

```typescript
// Em src/services/response-builder.ts
if (avgScore < config.SEARCH_CONFIDENCE_THRESHOLD) {
  answer = `[AVISO: confiança baixa — verifique com supervisor]\n\n${answer}`;
}
```

---

#### DUVIDA-02 — Informação não encontrada

Se nenhum chunk superar o threshold, o pipeline **não deve chamar o LLM**.
Retornar diretamente com `answer` padronizado e `source_document: []`.

Distinguir obrigatoriamente entre dois casos
(ver `src/services/response-validator.ts` → `classifyNotFound()`):

| Caso | Significado | Mensagem ao atendente |
|------|-------------|----------------------|
| `NOT_FOUND` | Tema não coberto pela base documental | "Não encontrei informação sobre [tema] na base atual." |
| `RETRIEVAL_FAILURE` | Tema coberto, mas busca retornou vazio | "Não consegui recuperar a informação. Tente reformular ou consulte [documento]." |

---

#### DUVIDA-03 — Documentos contraditórios

Quando `contradiction_flag: true`, a resposta deve:

1. Apresentar o valor da versão mais recente primeiro
   (ordenado por `metadata.data_vigencia` decrescente)
2. Informar que existe versão anterior com valor diferente
3. Recomendar confirmação com a área responsável

> Ver `prompts/system-prompt.md` → seção "Tratamento de contradições" (ADR-0003)

---

#### DUVIDA-04 — Carga perigosa identificada na query

Se a query contiver termos de carga perigosa
(lista em `src/services/response-validator.ts` → `DANGEROUS_GOODS_TERMS`),
injetar bloco de escalação **independentemente** do conteúdo da resposta:

```typescript
// Em src/services/response-builder.ts
// Injetado pelo pipeline, não gerado pelo LLM
const ESCALATION_BLOCK =
  "\n\n> **ATENÇÃO:** casos envolvendo carga perigosa requerem " +
  "tratamento pela Gestão de Riscos — ramal 4500.";
```

### 4. Glossário de linguagem ubíqua

> Agentes de IA e membros do time devem usar estes termos exatamente como definidos.
> Sinônimos proibidos estão listados explicitamente — modelos de linguagem conhecem
> esses sinônimos e podem usá-los naturalmente; a proibição explícita reduz esse risco.
>
> Este glossário deve ser transcrito integralmente na seção "Linguagem ubíqua"
> de `prompts/system-prompt.md`.

| Termo canônico | Definição | Sinônimos proibidos | Fonte |
|---|---|---|---|
| **frete especial** | Frete com peso acima de 500kg. Abaixo disso é frete padrão (sem procedimento documentado na base atual). | "frete pesado", "frete de carga grande" | PROC-042 |
| **carga perigosa** | Exclusivamente cargas classificadas nas classes 1–6 da ANTT (Res. 5.947/2021): explosivos (cl.1), gases (cl.2), líquidos inflamáveis (cl.3), sólidos inflamáveis (cl.4), oxidantes e peróxidos (cl.5), substâncias tóxicas e infectantes (cl.6). | "carga de risco", "carga sensível", "material perigoso" | POL-001 §3.2 |
| **cadeia de frio rompida** | Temperatura fora da faixa especificada na nota fiscal por mais de 30 minutos contínuos, conforme registro do sensor IoT. | "problema de temperatura", "carga descongelada" | POL-001 §3.2 |
| **CT-e** | Conhecimento de Transporte Eletrônico. Documento obrigatório em toda solicitação de devolução. | "nota fiscal", "comprovante", "documento de transporte" | POL-001 §3.3 |
| **coleta reversa** | Operação logística de recolhimento físico da mercadoria devolvida. Etapa dentro do processo de devolução — não é sinônimo de devolução. | "busca da mercadoria", "retirada", "retorno" | POL-001 §3.3 |
| **frete reverso** | Frete cobrado do cliente em caso de desistência. Calculado com os mesmos multiplicadores do frete original. | "frete de volta", "custo de retorno" | POL-001 §3.5 |
| **tier** | Classificação do cliente. Valores possíveis: `Gold`, `Silver`, `Standard`. Nenhum outro valor existe. | "categoria", "nível", "plano" | SLA-2024 §1 |
| **cliente Gold** | Contrato anual acima de R$ 500.000 OU mais de 200 operações/mês. Revisão semestral. | "cliente premium", "cliente VIP", "cliente Platinum" | SLA-2024 §1 |
| **cliente Silver** | Contrato anual entre R$ 100.000 e R$ 500.000 OU entre 50 e 200 operações/mês. Revisão semestral. | "cliente intermediário", "cliente médio" | SLA-2024 §1 |
| **cliente Standard** | Todos os demais clientes. Revisão anual. | "cliente básico", "cliente comum", "cliente normal" | SLA-2024 §1 |
| **incidente crítico** | Incidente que atende a pelo menos 1 de 4 critérios: (1) carga >R$100k com status desconhecido >6h; (2) carga perigosa com qualquer irregularidade; (3) >5 chamados do mesmo cliente em 24h sobre o mesmo problema; (4) risco à segurança de pessoas. | "chamado urgente", "incidente grave", "caso crítico" | SLA-2024 §3 |
| **SLA de primeira resposta** | Tempo até o primeiro retorno ao cliente, mesmo que seja apenas confirmação de recebimento. Diferente de resolução. | "tempo de resposta", "prazo de atendimento" | SLA-2024 §2 |
| **SLA de resolução** | Tempo até o problema ser efetivamente resolvido. Diferente de primeira resposta. | "prazo de fechamento", "tempo de solução" | SLA-2024 §2 |
| **multiplicador regional** | Fator aplicado ao valor base do frete conforme região de destino. ⚠ Contradição conhecida entre PROC-042-v1 e v2 — sempre apresentar ambas as versões. | "fator regional", "coeficiente de região" | PROC-042 §2.1 |
| **fator de peso** | Multiplicador aplicado ao frete conforme faixa de peso da carga. ⚠ Contradição conhecida entre v1 e v2. | "coeficiente de peso", "fator de carga" | PROC-042 §2 |
| **dias úteis** | Dias excluindo sábados, domingos e feriados nacionais. Nunca usar "dias" sem qualificação em contextos de prazo. | "dias corridos", "dias" (sem qualificação) | POL-001 §3.1 |
| **triagem** | Verificação de elegibilidade, documentação e prazo de um chamado de devolução. Prazo máximo: 4 horas úteis. | "análise inicial", "verificação" | POL-001 §3.3 |

### 5. Restrições que impactam geração de código

Ao gerar ou modificar os arquivos abaixo, respeitar obrigatoriamente:

---

#### `src/shared/types.ts`

- `QueryResponse.source_document` é array não-nullable. Nunca tornar opcional.
- `ClientTier` é union literal exaustiva: `'Gold' | 'Silver' | 'Standard'`.
  Nunca adicionar valores sem aprovação do Product Specialist.
- `DocumentRef` exige `doc_id`, `version` e `section` como campos obrigatórios.
  Sem estes três, a citação é estruturalmente inválida.

---

#### `src/functions/query/validator.ts`

- Validar presença e estrutura de `source_document` no output antes de retornar.
- Rejeitar queries com dados pessoais (CPF, CNPJ, dados bancários) com HTTP 400.
- Queries com tiers inválidos: não rejeitar — injetar instrução corretiva no
  contexto e registrar no log. O atendente não deve ver um erro por isso.

---

#### `src/services/response-validator.ts`

- `DANGEROUS_GOODS_TERMS`: lista configurável de termos que identificam carga
  perigosa. Nunca hardcodar inline fora desta lista.
- `MULTI_VERSION_DOCS`: lista de documentos com múltiplas versões ativas.
  Adicionar entrada sempre que um documento receber revisão sem arquivamento
  da versão anterior.
- `validateSources()`: bloquear respostas com `doc_id` sem `version`
  para documentos em `MULTI_VERSION_DOCS`.
- `classifyNotFound()`: distinguir `NOT_FOUND` de `RETRIEVAL_FAILURE`.
  As duas situações têm mensagens diferentes para o atendente.

---

#### `src/services/prompt-builder.ts`

- O system prompt é carregado de `prompts/system-prompt.md`.
  **Nunca hardcodar o prompt no código.**
- O context budget deve respeitar os limites de `src/shared/config.ts`:
  `SYSTEM_PROMPT_TOKENS`, `CHUNKS_TOKENS`, `HISTORY_TOKENS`, `QUERY_TOKENS`.
  Ver ADR-0002 para os valores e justificativas.
- Chunks de documentos com `contradiction: true` no índice devem ser
  recuperados em par (v1 e v2 juntos). Ver ADR-0003.

---

#### `prompts/system-prompt.md`

- Toda alteração deve ser registrada em `prompts/prompt-changelog.md`
  com: data, autor, motivo e resultado esperado.
- O prompt deve conter seção "Linguagem ubíqua" com o glossário
  da seção 4 deste arquivo transcrito — agentes sem acesso ao AGENTS.md
  devem ter o vocabulário disponível diretamente no prompt.
- O prompt deve conter seção "Contradições conhecidas" listando
  os campos com divergência entre PROC-042-v1 e v2.
